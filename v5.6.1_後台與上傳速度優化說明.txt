創世基金會草屯院｜工作申請與結案管理平台
v5.6.1 後台與上傳速度優化

【本版目的】
改善登入、案件列表、點開案件與檔案上傳完成後等待時間。
保留 v5.6.0 的電子章、分級審核、修改註記退件、20MB 上限及既有 Google 登入設定。

【速度優化內容】
1. 同一次 Apps Script 執行只開啟一次後台試算表，不再反覆 openById。
2. 白名單加入 60 秒短期快取；新增、修改、停用或刪除帳號時會立即清除快取。
3. 一般使用者開啟案件列表時不再讀取 Google Drive 母資料夾；管理員仍可正常使用雲端硬碟按鈕。
4. 點開案件清除紅燈時，不再重新下載全部案件資料。
5. 上傳等待期間改為每 2.5 秒只查詢上傳狀態。
6. 完整案件資料備援檢查延後至 15 秒後，之後每 10 秒最多一次，不再每 1.8 秒重抓全部案件。
7. 新建立的 Drive 檔案不再對每位使用者先執行 Permissions.list；直接設定必要的讀取權限並關閉共用通知信。
8. 上傳後的檔案網址、上傳者、案件狀態、核章與未讀欄位改成一次整列寫入。
9. 登入工作階段清理改為每 6 小時最多一次，並採批次讀寫，不再每次登入逐列檢查。
10. 寄信或操作紀錄偶發失敗時，不會再把已成功存入 Drive 的檔案誤判為整次上傳失敗。
11. Apps Script 執行紀錄新增 PERF_DASHBOARD 與 PERF_UPLOAD，可查看各處理階段耗時。

【不變更的項目】
1. Apps Script 執行身分仍是 hty0814ex@gmail.com。
2. 網頁應用程式仍允許所有人存取，再由平台登入及白名單控管。
3. Drive 母資料夾不需要公開。
4. Google Client ID、Drive API、試算表及既有部署網址都不需要更換。
5. 單一檔案上限仍為 20MB。

==================================================
更新方式
==================================================

第一步：更新 Apps Script 後台
1. 開啟 Apps Script 專案。
2. 開啟「程式碼.gs／Code.gs」。
3. 將原本內容全部刪除。
4. 複製「Code_Workflow_v5_6_1.txt」全部內容並貼上。
5. 儲存。

本版沒有新增資料欄位，不需要執行 setupSystem()。

第二步：更新原本的網頁應用程式部署
1. 右上角「部署」→「管理部署作業」。
2. 找到目前的網頁應用程式並按鉛筆圖示。
3. 版本選「新版本」。
4. 執行身分保持「我（hty0814ex@gmail.com）」。
5. 誰可以存取保持「所有人」。
6. 按「部署」。

請更新原部署，不要建立新的部署；原本 /exec 網址不變。

第三步：更新 GitHub 前台
1. 到 GitHub 的 Genesis-caotun／Work。
2. 上傳本包的 index.html，取代原本檔案。
3. Commit changes。
4. 等待約 1 至 3 分鐘。
5. 開啟：
   https://genesis-caotun.github.io/Work/?v=561
6. 頁首應顯示 v5.6.1。

==================================================
建議測試
==================================================

1. 使用社資帳號登入，確認案件列表可正常顯示。
2. 點開有紅燈的案件，紅燈應立即消失，畫面不應整頁等待重新載入。
3. 上傳一份 1MB 至 5MB 的 PDF，確認可正常送到副組長。
4. 以副組長、院長及督導測試沿用上一版、核章、修改退件。
5. 確認各帳號仍可從網站下載案件檔案。
6. Apps Script「執行項目」中可查看：
   PERF_DASHBOARD：登入驗證、白名單、案件列表及總耗時。
   PERF_UPLOAD：驗證、解碼、Drive 儲存、分享權限、試算表及通知耗時。

【速度說明】
Apps Script 偶爾仍可能出現 Google 端冷啟動延遲；大型 PDF 也仍會受實際網路上傳速度影響。本版主要縮短後台重複讀取，以及檔案傳完後仍長時間等待處理的情況。
