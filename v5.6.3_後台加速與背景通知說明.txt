創世基金會草屯院｜工作申請與結案管理平台 v5.6.3
後台加速與背景通知版－更新步驟

一、先更新 Apps Script 後台
1. 開啟目前的 Apps Script 專案。
2. 打開「程式碼.gs」，全選並刪除舊內容。
3. 將 Code_Workflow_v5_6_3.txt 的全部內容貼上並儲存。
4. 在編輯器上方的函式選單選擇 setupPerformanceV563。
5. 按「執行」一次；若 Google 要求授權，請用部署者帳號完成授權。
6. 執行完成後會：
   - 建立「通知佇列」工作表。
   - 建立每分鐘一次的背景處理排程。
   - 先同步 2 個既有案件的資料夾權限。
   - 其餘既有案件會在背景每分鐘同步 2 個。

重要：這次不需要再執行 setupSystem()，原有資料不會重建。

二、重新部署 Apps Script
1. 點「部署」→「管理部署作業」。
2. 編輯現有的網頁應用程式部署。
3. 版本選「新版本」。
4. 執行身分維持「我（hty0814ex@gmail.com）」。
5. 誰可以存取維持「所有人」。
6. 完成部署；原本的 /exec 網址不需要更換。

三、更新 GitHub Pages
1. 到 GitHub 的 Work 儲存庫。
2. 用本包的 index.html 覆蓋儲存庫根目錄的 index.html。
3. Commit changes。
4. 等 GitHub Pages 更新後，以網址測試：
   https://genesis-caotun.github.io/Work/?v=563

四、更新後的速度與行為
- 新案件：建立案件時只設定一次案件資料夾權限。
- 後續上傳：檔案直接繼承案件資料夾權限，不再逐人分享每一份檔案。
- 舊案件：背景排程逐步轉換；尚未轉換的案件第一次上傳可能仍會多等一次。
- 通知信：上傳完成不必等待寄信；通知通常會在下一次背景排程寄出，約 1 分鐘內。
- 案件列表：加入短期快取，登入與重新整理通常會更快。
- 白名單停用或刪除：仍會撤銷該帳號的資料夾與舊檔案權限，這類低頻管理動作可能需要較久。

五、建議測試
1. 執行 setupPerformanceV563() 後，先等 2～5 分鐘。
2. 用社資帳號建立一個測試案件並上傳 PDF。
3. 用副組長帳號沿用檔案、核章並送出。
4. 確認案件狀態立即更新，通知信稍後收到。
5. 到 Apps Script「執行項目」查看 PERF_UPLOAD；完成資料夾轉換後，share 應接近 0ms。

六、限制說明
- 20MB 檔案仍會先在瀏覽器轉成 Base64，再傳給 Apps Script；檔案越大、裝置越慢，等待仍會增加。
- 若 v5.6.3 上線後，大檔案仍無法達到需要的速度，下一階段應改用 Firebase Storage 的可恢復分段上傳；那會是 v6 架構升級，不是再調 Apps Script 參數。
